What it does

Date bugs hide in someone else’s morning.

They pass every test on your laptop, at your time of day. tzproof goes where they live.

Root cause: “Today” came from toISOString(), the UTC date. “Next invoice” used setMonth(+1), so 31 January became 3 March.
-  const isoDay = now.toISOString().slice(0, 10);
+  const isoDay = `${now.getFullYear()}-${pad(now.getMonth() + 1)}-${pad(now.getDate())}`;
-  invoice.setMonth(invoice.getMonth() + 1);
+  const invoice = new Date(y, m, Math.min(now.getDate(), lastDay));

FAQ

Questions

Does it change anything in my app?

No. tzproof changes the browser, not your app: Chrome starts in the time zone you pick, and the page’s clock is moved before any of your code runs. Your server keeps its own clock.

Why not trust Kane’s own pass or fail?

Kane is great at using a page like a person, and tzproof asks it to check each date too. But in our real runs its own check passed a wrong date in 1 of 5 cells. So tzproof takes the dates Kane read and compares them with the right calendar day in code. When they disagree, the cell says so.

Can Claude fix my site from here?

Live fixes run on our demo app, where Claude may edit only a private copy. For your own site, tzproof gives you the exact prompt with Kane’s evidence for every red cell, and a Stop hook so your coding agent can’t finish while a clock is red.

What does it cost?

tzproof is free and open source (MIT). Each cell is one Kane CLI run, about 15 to 30 Kane credits. The hosted version has a small daily allowance; install it to use your own Kane account.

What can’t it do yet?

It moves the browser’s clock, not your server’s. Code that reads time without Date is not moved. And the hosted version tests public sites only; use the CLI for localhost.
